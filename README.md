# 木犀游戏机 · Muxi Console

本仓是从空目录建立的独立 Minecraft 模拟器集成。Cartridge 只提供公开功能和体验参考；本仓不继承其 Git 历史，不导入其代码、协议、native host、模型、贴图、界面或测试。旧 `muxi-arcade/` 保留为历史验证，不能进入本产品构建输入。

目标：Minecraft 1.21.1、NeoForge 21.1.250、Java 21；modId `muxi_console`，Java 包 `net.muxigame.console`。原创代码、界面、模型、像素贴图、构建脚本和测试按[MIT](LICENSE)开源，公开仓库为[GitHub · muxigame/muxi-console](https://github.com/muxigame/muxi-console)。第三方模拟器及依赖保留自己的许可证，MIT不替代它们的源码和许可证交付要求。源码公开与正式二进制/服务器发布分别核验；下文开发候选及历史运行记录不代表已上线。

当前预览版本为 **0.1.0**，Windows x86-64 / Minecraft 1.21.1 / NeoForge 21.1.250 / Java 21。支持21平台、22款原创设备、上传刻录卡带、多人控制、双全屏和浏览器屏幕联动；存档按机器与游戏内容分别保存，借卡不带进度，同机换同内容卡可续玩。掌机单卡槽、实际外露卡、真实加载进度、27格薄卡册、居中物品图标和2×2×1电脑显示器均保留。第三方游戏ROM及原厂BIOS由玩家依法自行准备。

0.1.0包内附15个第三方核心的完整对应源码、固定子模块、构建说明和原始许可证；源码附件不会被模拟工作进程加载。18组3163项检查、390资源/30489项校验以及重建MD/PCE的90项输入与冷恢复检查已通过。发行候选531648674字节，SHA256 `370f59645046e97386f5b89b3ba44d13085e37f29dccd44f4b7dec130ccc2f44`；真实整合包两客户端已完成掌机、卡册、刻录机和普通物品掉落检查，测试环境正常退出；线上发布正在进行。历史开发与图像验收边界见[状态](docs/STATUS.md)、[机器存档审核](docs/MACHINE-SAVES.md)和[完整范围](docs/PLATFORM-COMPLETION.md)。本地build目录及历史原图不随Git仓库发布。

功能目标：玩家上传自己有权使用的 ROM，服务器校验和存储，刻录成可转交的实体卡带；原创主机、掌机、电视、控制器与刻录机；多人控制、键位绑定和 GLFW 手柄。游戏内权利声明默认 false，换文件重置；投诉与客服在云平台，不增加游戏内客服表单。已取得的本地 ROM 缓存不能远程撤回。

开发模块：

- `domain/`：平台和 ROM、内容存储、上传状态机、持卡/控制权限、输入时间线，不依赖 MC。
- `runtime/`：独立 Java/JNA 子进程调用公开 libretro ABI，MC 进程不装载核心；使用我们自己的请求/响应协议。
- `mc/`、`client/`：NeoForge 注册、网络、物品、方块、会话、原创 GUI、动态画面、音频与输入。
- `assets/` 和资源生成工具：独立编写真实年代设备感的像素几何与材质；公开实物仅作比例/部件参考，不导入第三方模型、纹理、logo或游戏封面。

产品源码只在本真实仓开发。构建依赖从总仓共享 SDK 只读解析；Minecraft 只通过总仓 `scripts/ops/test_environment.py` 分配统一测试环境。没有测试通过之前不声称兼容，没有生产授权不发布。

## 使用

服务端和所有客户端安装相同版本的本模组。当前只构建 Windows x86-64、MC1.21.1 / NeoForge21.1.250；无需 YACL。JNA、独立 Java 工作进程、已登记核心和N64所需的LWJGL由候选包提供，没有第三方游戏下载功能。完整操作与逐平台按键见[玩家指南](docs/USER-GUIDE.md)。

1. 准备空白卡带、刻录机、主机或掌机、屏幕和控制器；空白卡带放在物品栏中。新电脑显示器占2×2×1范围，面板本身很薄，下面有支架和底座，放置前须留足四格空间。
2. 使用刻录机，拖入或选择有权使用的游戏文件，确认本次上传和卡带使用的授权，再点“上传并刻录”。必要时手选平台；换文件会撤销勾选。刻录好的卡带进入物品栏。
3. 手持卡带使用主机插入，再手持控制器使用主机接入控制席。空手使用主机打开设备面板，开机、连接附近屏幕，依次选择 P1/P2；每名玩家占一个接口。
4. 键位使用MC自己的“选项→控制→按键绑定”，按平台分类保存到options.txt，手柄选择和映射也在原生控制列表。常规默认方向 WASD、A=J、B=K、X=I、Y=U、Start=Enter、Select=右 Shift，MD/N64/FDS另有平台默认键位；不再使用独立键位页或F/F8切换。
5. 掌机：背包中用鼠标拿起指定卡带、右键掌机装入单卡槽；空鼠标右键取出原卡，也支持反向拿掌机右键卡带槽。选中时仅短暂提示“右键切换全屏模式，Esc退出全屏”；右键先显示完整机身，再切纯画面细框全屏，Esc只退出并释放输入。首次缺缓存时，内屏和全屏显示真实加载进度，完成后切游戏。收起掌机会正常保存；运行/保存中保护卡槽，原卡名称/自定义数据保持。双手/惯用手与整颗按钮变蓝继续保留，实际插入卡带在外部插槽显示。
6. 底座：正常保存离开后，手持整台掌机右键放入掌机底座；底座展示原机型并低位缓慢旋转。使用底座面板开机、连接附近大屏和加入P1。正常离开后可从面板或空手潜行取回原掌机，卡带和自定义数据保持。详见[掌机与底座](docs/HANDHELD-DOCK.md)。

卡带可以流转，ROM内容按SHA256去重，进度按“机器UUID＋ROM SHA256”保存；同机换同内容卡继续，借给另一台机器只提供游戏内容。整机转交会携带该机各游戏的进度；底座与屏幕不拥有独立存档。世界下的ROM与已提交状态统一备份，旧卡归属存档保留且不自动迁入新机器。普通软件核心使用同核心身份的状态同步；N64/MAME由一名主控运行核心，其他控制席发送输入并接收音画，不下载ROM或存档。主控正常离开会保存并结束本次会话，其他玩家随后可从P1恢复，不承诺不中断迁移。每约300个模拟帧自动保存，正常离开前再保存；断电或强制退出可能丢失最近一次保存后的进度。

内置屏及可选WebDisplays/MCEF可显示同一局。手持控制器潜行使用有权限的浏览器屏进行绑定，再次使用解绑；纯旁观者只接收画面，不取得ROM。街机ZIP由刻录界面封装为自己的`.mxarc`，可明确选择必要的父集或BIOS集；FDS/Lynx所需固件由玩家自行合法提供，详见指南。

## 构建和测试

从本仓执行：

```powershell
python -B tools/generate_assets.py --check
python -B tools/fetch_cores.py --offline
python -B tools/build.py --name <新的构建名称> --tests
```

从固定源码重新构建两核心后，维护者运行 `python -B tools/export_rebuilt_sources.py` 导出不含无关主机环境的公开源码资料，再运行 `python -B tools/release_sources.py --prepare` 和 `--verify`，最后使用 `tools/build.py --name <新名称> --tests --release` 正式打包。现有成功产物会拒绝覆盖，不需对本轮冻结缓存重跑。独立worker构建及交付源码的重建方法见[构建说明](docs/BUILD.md)。

核心获取参数见 `python -B tools/fetch_cores.py --help`；只读校验不更新 pin，初次获取必须显式选核心。运行测试必须从总仓统一分配 `client-N/runs/`，不在本仓创建 Minecraft 安装。默认编译预算512MiB/单CPU，纯测试128MiB/单CPU，独立模拟工作进程256MiB/单CPU。

第三方组件与实际验证边界见 [状态](docs/STATUS.md)、[核心清单](third-party/cores.json)、[运行时](docs/RUNTIME.md) 和 [原创美术](docs/ART-DIRECTION.md)。第一方部分使用 MIT，第三方模拟器保留各自许可证；正式二进制必须交付精确对应源码和完整许可，尚未完成的核心继续保持 `releaseReady=false`。实体手柄按键/热插拔、实际音响听感、各平台代表性合法游戏、Linux、光影仍须分别验收；掌机联机线尚未实现。本仓当前未生产发布。
