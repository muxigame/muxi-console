# 木犀游戏机 · Muxi Console

本仓是从空目录建立的独立 Minecraft 模拟器集成。Cartridge 只提供公开功能和体验参考；本仓不继承其 Git 历史，不导入其代码、协议、native host、模型、贴图、界面或测试。旧 `muxi-arcade/` 保留为历史验证，不能进入本产品构建输入。

目标：Minecraft 1.21.1、NeoForge 21.1.250、Java 21；modId `muxi_console`，Java 包 `net.muxigame.console`。第一方代码和资产自行实现，底层模拟器作为单独登记的第三方组件选择，许可与来源分开记录。当前尚未指定公开发行许可，未发布或改变生产。

当前为[手持体验候选](build/held-feel-04/muxi-console-0.1.0-dev.1+mc1.21.1.jar)：增加玩家皮肤手臂、单手/双手及惯用手姿态，九掌机薄约27–29%、动作键收小与细胶囊功能键；可直接设置各平台键位，专注游玩时隔离世界输入，实际按钮显示天蓝高光。354项资源/23534检查、2425项纯Java检查通过；[本轮32次实机采图](build/held-feel-review/index.html)及[逐项审核](docs/HANDHELD-FEEL.md)记录77项原断言与16项独立续办的联合范围，原回执占用失败保留。前轮22款年代机体/21媒体与配件的[53张原图](build/pixel-realistic-review/index.html)保留历史；大屏资源、核心与worker原字节保持。21平台、多人、上传卡带、底座及WebDisplays/MCEF证据仍分轮保留，见[开发状态](docs/STATUS.md)和[完整范围](docs/PLATFORM-COMPLETION.md)，不代表全部游戏兼容。

功能目标：玩家上传自己有权使用的 ROM，服务器校验和存储，刻录成可转交的实体卡带；原创主机、掌机、电视、控制器与刻录机；多人控制、键位绑定和 GLFW 手柄。游戏内权利声明默认 false，换文件重置；投诉与客服在云平台，不增加游戏内客服表单。已取得的本地 ROM 缓存不能远程撤回。

开发模块：

- `domain/`：平台和 ROM、内容存储、上传状态机、持卡/控制权限、输入时间线，不依赖 MC。
- `runtime/`：独立 Java/JNA 子进程调用公开 libretro ABI，MC 进程不装载核心；使用我们自己的请求/响应协议。
- `mc/`、`client/`：NeoForge 注册、网络、物品、方块、会话、原创 GUI、动态画面、音频与输入。
- `assets/` 和资源生成工具：独立编写真实年代设备感的像素几何与材质；公开实物仅作比例/部件参考，不导入第三方模型、纹理、logo或游戏封面。

产品源码只在本真实仓开发。构建依赖从总仓共享 SDK 只读解析；Minecraft 只通过总仓 `scripts/ops/test_environment.py` 分配统一测试环境。没有测试通过之前不声称兼容，没有生产授权不发布。

## 使用

服务端和所有客户端安装相同版本的本模组。当前只构建 Windows x86-64、MC1.21.1 / NeoForge21.1.250；无需 YACL。JNA、独立 Java 工作进程、已登记核心和N64所需的LWJGL由候选包提供，没有第三方游戏下载功能。完整操作与逐平台按键见[玩家指南](docs/USER-GUIDE.md)。

1. 准备空白卡带、刻录机、主机或掌机、屏幕和控制器；空白卡带放在物品栏中。新屏幕默认占3×2格，厚1/8格，放置前须留足六格空间。
2. 使用刻录机，拖入或选择有权使用的游戏文件，确认本次上传和卡带使用的授权，再点“上传并刻录”。必要时手选平台；换文件会撤销勾选。刻录好的卡带进入物品栏。
3. 手持卡带使用主机插入，再手持控制器使用主机接入控制席。空手使用主机打开设备面板，开机、连接附近屏幕，依次选择 P1/P2；每名玩家占一个接口。
4. 操作视角键（默认F，可改）在电视视角/全屏之间切换，F8 暂回世界并保留控制席，Esc 保存并离开。游玩右上“按键设置”或设备面板可按平台保存键盘、实体手柄和模拟方向映射；常规默认方向 WASD、A=J、B=K、X=I、Y=U、Start=Enter、Select=右 Shift，MD/N64/FDS另有平台默认键位。实体手柄须在设置中启用。
5. 掌机：潜行使用装入兼容卡带，拿起即可看到运行画面与玩家手臂；操作视角键进入手持操作、右键进入全屏后才采游戏输入，普通持有时仍正常走路。主手且副手为空时双手支撑，单手左右遵从惯用手；实际游戏按钮触发时天蓝高光。Esc正常保存后不会立即自动重开；收起再拿出可恢复。取卡前先正常离开。
6. 底座：正常保存离开后，手持整台掌机右键放入掌机底座；底座展示原机型并低位缓慢旋转。使用底座面板开机、连接附近大屏和加入P1。正常离开后可从面板或空手潜行取回原掌机，卡带和自定义数据保持。详见[掌机与底座](docs/HANDHELD-DOCK.md)。

卡带可以流转，存档按实体卡带 UUID 保存，ROM 内容按 SHA256 去重。普通软件核心使用同核心身份的状态同步；N64/MAME由一名主控运行核心，其他控制席发送输入并接收音画，不下载ROM或存档。主控正常离开会保存并结束本次会话，其他玩家随后可从P1恢复，不承诺不中断迁移。每约300个模拟帧自动保存，正常离开前再保存；断电或强制退出可能丢失最近一次保存后的进度。

内置屏及可选WebDisplays/MCEF可显示同一局。手持控制器潜行使用有权限的浏览器屏进行绑定，再次使用解绑；纯旁观者只接收画面，不取得ROM。街机ZIP由刻录界面封装为自己的`.mxarc`，可明确选择必要的父集或BIOS集；FDS/Lynx所需固件由玩家自行合法提供，详见指南。

## 构建和测试

从本仓执行：

```powershell
python -B tools/generate_assets.py --check
python -B tools/fetch_cores.py --offline
python -B tools/build.py --name <新的构建名称> --tests
```

核心获取参数见 `python -B tools/fetch_cores.py --help`；只读校验不更新 pin，初次获取必须显式选核心。运行测试必须从总仓统一分配 `client-N/runs/`，不在本仓创建 Minecraft 安装。默认编译预算512MiB/单CPU，纯测试128MiB/单CPU，独立模拟工作进程256MiB/单CPU。

第三方组件与实际验证边界见 [状态](docs/STATUS.md)、[核心清单](third-party/cores.json)、[运行时](docs/RUNTIME.md) 和 [原创美术](docs/ART-DIRECTION.md)。模拟器核心仍是第三方组件；第一方公开发行许可尚未指定，精确对应源码及许可交付未闭合，`releaseReady=false`。实体手柄按键/热插拔、实际音响听感、各平台代表性合法游戏、Linux、光影和完整整合包共存仍须分别验收；掌机联机线尚未实现。本仓未生产发布。
