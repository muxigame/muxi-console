# 可选对象存储

此功能仍在本轮候选开发与验收中，尚未发布。无云存储配置时，ROM继续保存在当前世界的`muxi-console/content`；机器存档继续保存在该世界的`muxi-console/states/machines`。

维护者仅在服务端JVM启动参数中显式指定`-Dmuxi.console.storageConfig=<私有配置文件的绝对路径>`才启用对象存储。配置文件放在服务端私有目录，不能放进产品仓库、模组资源、整合包或发布清单。模组没有内置桶、地址或凭据，也不会扫描环境变量寻找它们。未指定参数或指定文件不存在时使用本地存储；现存配置格式错误会明确失败，防止悄悄把内容写进另一套存储。

外部文件是UTF-8 properties，必填字段为`provider`（`s3`或`oss`）、`endpoint`（HTTPS源地址）、`bucket`、`region`、`keyPrefix`、`accessKeyId`、`accessKeySecret`。可选`sessionToken`、`addressingStyle`（S3可选`virtual`或`path`，OSS必须`virtual`）、`ticketSeconds`（默认900，允许1～3600）。本说明不包含本服实际配置。建议独立服务身份仅允许该前缀的对象读取和写入，不授予桶设置或其他前缀权限。

OSS还必须由维护者通过云API确认桶从未启用版本控制，并在私有文件写`ossVersioning=disabled`；`Enabled`和`Suspended`均不满足前置条件。OSS的禁止覆盖请求头在版本控制桶中不保证禁止覆盖，因此不能跳过这一核验。S3条件PUT使用`If-None-Match: *`；OSS使用`x-oss-forbid-overwrite: true`。对象路径由前缀、SHA256前两位及完整SHA256生成。

客户端先检查自己选中的文件并放入按哈希索引的缓存，再向服务器申请短期PUT凭证；ROM正文从客户端直达对象存储。重复哈希在HEAD信息匹配时不再上传。完成时服务器只做HEAD，核对大小和签名约束下的SHA/平台元数据，绝不下载ROM正文回服务器。S3另外提交原文件SHA256对应的原生校验头；OSS元数据并不等于存储服务验证了正文SHA256。客户端下载时自行校验实际内容，保留按哈希/大小标识的断点；短期GET凭证允许Range续传。凭证不写进会话上下文、存档或日志。

刻录权限、当前刻录机窗口、事务UUID和空白卡槽均在服务器重新检查。云端HEAD操作放在独立有界后台队列，物品变更只在Minecraft线程执行。关闭窗口、取消和迟到响应按原事务撤销，不影响新窗口的卡带。

超过单次PUT上限的文件采用16MiB分片直传，服务器只处理分片票据、ETag列表和合并控制请求，不接收分片正文。正常取消、超时和关闭会尝试AbortMultipartUpload；停服清理最多等待20秒，随后中断未完成的云请求，防止对象服务故障拖住服务器退出。维护者还应给该专用前缀设置清理未完成分片上传的生命周期规则，兜底断电、进程崩溃和云端不可达；不可覆盖桶中其他业务的既有规则。该规则只处理未完成分片，不能删除完整ROM或存档。

既有ROM迁移入口为`tools/migrate_content.py`，显式提供`--name`、`--config`、`--content`和`--java-home`。默认只列本地对象数量与总字节；加`--apply`才逐哈希条件PUT、HEAD确认并更新同世界的元数据。不做对象正文GET，不改机器存档，不删除本地原ROM；重复执行复用已存在对象。完整发行JAR也可直接运行`net.muxigame.console.ops.ContentMigration`入口，参数是私有配置路径、世界content路径和可选`--apply`。迁移及配置变更属于生产维护，须按当次授权和正常发布流程执行。

移除云配置后，已保留的本地ROM仍可使用；只有远程对象的卡带会提示服务器未启用云存储，不能伪装成完整本地内容。此时重新上传同内容可以恢复本地副本，SHA相同的本地/云登记只占一次世界逻辑内容额度。
