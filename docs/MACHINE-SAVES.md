# 机器存档与卡带收纳盒

2026-11-08，独立真实仓 `muxi-console/`，从 `dev@d1b2ea43cbe70bdf638b7b072538abcf2d365a43` 开发，未发布。第一方实现只使用本仓源码和MC/NeoForge公开接口。

## 玩家行为

存档归掌机或桌面主机所有，每台机器按精确ROM内容分别保存。卡带的独立UUID继续用于实物身份、插槽和持卡权限，不再作为进度归属。

| 操作 | 进度 |
| --- | --- |
| 同一台机器换入同一内容的另一张卡 | 继续这台机器已有进度 |
| 把卡借给另一台机器 | 对方使用自己的进度；没有则从头开始 |
| 原机器换不同游戏后再换回来 | 各游戏进度分开，原进度保留 |
| 整台机器转交给别人 | 机器身份与各游戏进度一起转交 |
| 掌机安装到底座、再取回 | 使用原掌机身份与进度 |
| 桌面主机生存模式拆除再放置 | 掉落物保留原机器身份 |
| 更换底座或显示器 | 不改变来源机器的存档 |

游戏内容以SHA256区分。改标题、换卡号不会创建新进度；内容不同的修订版、汉化和修改版分别保存。仍须使用兼容机型和一致的模拟器核心，无法使用不同核心的状态时明确报错。

27格卡带收纳盒同时支持便携和摆放。手持右键打开，潜行右键摆放；摆放后右键打开。仅接收游戏卡带和空白卡带，拒绝杂物、掌机和收纳盒。游戏卡每格一张，空白按原有堆叠上限。便携打开时锁住自身来源格，普通、快捷、数字键/副手、拖拽和双击收集合并不能转移来源盒。每次实际槽位变更即写入盒子物品；摆放后写入方块实体。生存拆除掉落整盒并保留完整卡ItemStack、名称和自定义数据。

## 世界存储与旧候选

服务端根目录仍为 `server.getWorldPath(LevelResource.ROOT)/muxi-console/`：

- `content/`：原ROM及元数据，按SHA256去重。
- `states/machines/<机器UUID>/<ROM SHA256>/`：按机器、游戏分开的原子状态库，包含当前/上一代保护、上传临时文件和核心身份。
- `states/cards/`：旧候选的卡归属存档，仅保留原文件；新实现不读取、不迁移、不覆盖。
- 玩家物品中的机器UUID、掌机卡槽、便携盒内容在世界playerdata中，摆放设备和盒子在对应维度区块中。

完整备份世界即可同时保留原ROM、已提交进度和机器/物品位置。这里没有增加自动备份服务，也不把客户端ROM缓存当权威存档。旧候选没有记录卡进度原本属于哪台机器，自动分配会重新造成借卡携带进度；因此保留原档，当前没有显式迁移入口。正常保存离开后再取卡、转交或拆机；强关、死亡或拆除运行中的设备只能以最近已提交进度为准。

## 实现范围

`MachineData`在服务器为单个掌机/桌机物品分配独立UUID，不改卡号、机型或名称。桌机方块保存独立机器UUID，摆放采用物品UUID，掉落时写回；底座使用安装掌机的UUID。会话固定机器和内容键，当前持机验证、并发机器保护和每个状态传输都校验该归属。

`MachineStateVault`在新的机器/内容命名空间复用原StateVault的分块、整档SHA、原子头替换、两代保护及恢复。整体1GiB配额合计所有机器和游戏的完整代际与在途上传，限制同一上传者及同一机器/游戏的并发上传。单个状态仍限32MiB、分块24576字节，未完成上传不会替换已有存档。

`StateVault`新增配额读取接口及可选的完整命名空间校验。新机器库采用V2代际元数据，每代都写入并核对`机器UUID:ROM SHA256`，从其他游戏或机器目录复制来的代际会被拒绝，不能仅凭相同核心或合法状态SHA混入。默认旧构造仍使用原V1格式；旧`states/cards/`既不打开，也不转换。新状态实文件位于`states/machines/<机器UUID>/<ROM SHA256>/cards/<机器UUID>/<代际UUID>.state`；内层`cards`是复用存储组件的目录名，其UUID在这里表示机器，和当前卡带UUID无关。

客户端会话、周期保存和正常退出均携带固定的`machine`及`content`字段，服务端核对控制席、实际机器、卡带和联合键，客户端读取前再次校验归属及核心身份。本地核心保存目录也改为`muxi-console/machine-saves/<机器UUID>/<ROM SHA256>/`，不再从旧卡号目录默认继承本地进度。启动失败后的短暂错误反馈绑定同一台机器及卡带，避免另一台机器误显示该错误。客户端ROM传输、既有第三方核心/worker、多人角色、双全屏、外露卡带和电脑屏功能保留。

轻量检查已完成旧StateVault的192项及新增MachineStateVault的24项，覆盖联合键隔离、重开、并发锁、跨库配额、旧档保留与外来命名空间拒绝；这些是纯存储检查，不替代MC内普通插卡、拆放和保存验收。

收纳盒使用原生菜单与箱子界面。服务端槽位限制和容器放入检查共同拒绝非卡，便携来源按实际服务器ItemStack与来源格验证，方块菜单遵从原生距离/方块存活检查；放置/拆除使用标准物品容器组件保留完整内容。网络协议为 `mx-console-3`，两端须安装同一候选，拒绝混用前一轮协议。
